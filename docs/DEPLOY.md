# TurfOS — launch guide

Files: `../index.html` (public site), `../pages/app.html` (the app), `../pages/privacy.html`, `../pages/terms.html`. Images are in `../assets/images/`, stylesheets in `../css/`, scripts in `../js/`, the D1 schema in `../database/schema.sql`, and the sample import file in `../templates/`.
It is a static site: no server needed.

## 1. Before you publish
- In `../index.html`, replace `YOUR_EMAIL@example.com` with your real address.
- Write real Privacy and Terms text in `../pages/privacy.html` / `../pages/terms.html` (they are placeholders).
- Read the "Known limits" below.

## 2. Put it online (pick one, all have free tiers)
- **Netlify Drop (easiest):** go to app.netlify.com/drop and drag this whole folder in. You get a live https link in seconds.
- **Cloudflare Pages / GitHub Pages:** upload the folder as a repo and enable Pages.

## 3. Get your own domain
1. Buy a domain (Cloudflare Registrar, Namecheap, Porkbun, etc.).
2. In Netlify: Domain management -> Add custom domain, then follow the DNS instructions it shows.
3. HTTPS is issued automatically once DNS is pointed.

## Known limits (important)
- **Actual cut timing:** The Dashboard now starts a real elapsed-time cut clock. Pause for travel or breaks, resume, then finish and save the measured duration; the timer survives a page reload on the same browser. The starting estimate is 33 minutes per lawn, editable in Settings. After timed services are recorded, each property's estimate uses the median of its five latest timed cuts and feeds the weekly schedule. Coverage and overlap entered at finish are crew estimates, not GPS measurements. This is a single active timer stored in one browser; use a shared backend for concurrent crew timers and dispatch.
- **Tree-covered roofs:** The Property Map compares OSM, Microsoft, county, and any additional GIS building polygons. If there is no house-sized footprint, only one agreeing roof source, or the user flags heavy tree cover, automatic parcel mowing lines pause until the mapped house is reviewed and confirmed or the house is traced with **Mark house or driveway**. Confirming a roof is a visual/on-site decision, and refreshing mapped footprints clears confirmation. Settings can query an extra CORS-enabled ArcGIS polygon layer, including a county layer derived from classified LiDAR. The app does not process raw LiDAR point clouds or infer hidden roofs from 3D terrain; **Inspect USGS LiDAR** opens an external viewer. Historic county outlines can be outdated. Check roof and driveway cutouts before dispatch.
- **Weekly scheduling:** Business → Weekly Schedule assigns each property one stop per Monday–Sunday week. It counts a logged mow as complete for that week, rolls plans forward, and can show the next week. Set daily crew hours, an optional shop/start address, and preferred weekdays; move individual stops and rebuild remaining assignments when plans change. Unmapped properties remain on the schedule but need coordinates before route mapping. Daily stop order uses proximity and a route improvement heuristic with approximate driving time; the **Optimize route on roads** button queries the public OSRM demo endpoint when available. Neither method guarantees the globally shortest trip or accounts for crew shifts, traffic, travel home, commercial road restrictions, forecast shutdowns, or multiple crews. If capacity is exceeded the day is marked. Plans and service logs remain in this browser only; a shared crew dispatch calendar needs a backend.
- **Summit County GIS parcels are built in.** For Summit County, Ohio, the app first searches the county's address point layer, then matches the entered house number and street to the county tax parcel's recorded `siteaddress`. It falls back to a spatial point query if there is no exact GIS address match. It displays the parcel ID and match method where available. For work outside the county, set a public ArcGIS polygon layer URL in Business → Settings (`/FeatureServer/0` or `/MapServer/0`; the layer number can vary). Address lookup and county data must be reachable in the user's browser. A provider requiring a secret API key needs a server-side integration.
- **If the wrong parcel is selected:** Open Property Map, choose **Select correct parcel on map**, and tap the middle of the correct lot in the 2D satellite view. The parcel ID/address from the county data is shown when present. This corrects the selected lot and reloads nearby obstacles. County linework and satellite photos can still have different georeferencing; the app does not alter the county's legal boundary geometry to fit the photo.
- **Compare aerial imagery:** The Property Map can switch between Esri satellite imagery and Summit County's April 2021 orthophoto in 2D. The county aerial may make the county GIS boundary easier to interpret, but it is older imagery and switching photos does not change the GIS parcel line. The 3D terrain view uses Esri imagery. If the county image service cannot load, Esri imagery remains visible underneath.
- **House exclusion:** After an address lookup, the app searches the whole parcel plus a margin for OpenStreetMap buildings and driveways, Microsoft's nationwide footprints derived from aerial imagery, and Summit County building footprints. It merges relevant roof polygons and clips the 2D and 3D passes around a conservative 1.2 m clearance around each detected roof. The search happens before automatic lines are drawn. If the sources fail or only small outbuildings are found, the automatic draft is paused until you draw the house with **Mark house or driveway** as a No-cut area. Data can still be missing or offset; confirm the red roofs on satellite imagery.
- **Existing properties:** Previously saved properties with a GIS parcel automatically refresh their building lookup when opened in this release. Draft cut lines stay hidden during the refresh so cached incomplete footprints do not keep sending lines across a house.
- **Historic county buildings:** Summit County's layer describes footprints from 2000. It supplements the newer sources, but may contain obsolete buildings. Review every suggested roof and remove obsolete shapes.
- **Building data licence:** The nationwide Microsoft building-footprint data is offered under ODbL. The app displays attribution when those shapes are used; review the licence obligations before a commercial launch or distributing a derived dataset.
- **3D satellite terrain:** Property Map has a 2D/3D toggle. The 3D view drapes Esri satellite images over an Esri elevation model in Cesium and shows the same parcel, turf, no-cut areas, and bold numbered cut lines. It needs WebGL and internet access. The 3D surface is terrain, not a photogrammetric model of roofs or driveways. Photorealistic 3D buildings would require a separate 3D tiles provider and API credentials/billing.
- **Map workflow:** The Property Map walks through Find property → Confirm parcel → Plan cut. The 2D/3D switch and aerial imagery selector are next to the map; the county aerial selector is available in 2D.
- **Automatic provisional mowing area.** After an address finds a GIS parcel and checks for houses, the parcel outline becomes a green provisional mowing area in 2D and 3D. Roof footprints and contained no-cut shapes become holes in the green area; buildings crossing a parcel edge remain red overlays. Yellow passes are clipped against every detected building, driveway corridor, manually drawn No-cut/weed-whack zone and parcel hole, even where a display hole cannot be drawn. Overlapping roof polygons are merged for the display. The gross parcel extent is labeled as such and is not a measured turf area. A manually traced turf zone replaces the provisional area; existing traces can be retained and switched back with **Use property line as mow area / Use traced lawn**. Parcels above 2,000,000 ft² require a manually traced lawn to keep the browser preview manageable.
- **Review every draft.** A parcel includes structures, paving, beds and sometimes land that is not turf. Address geocoders can select the wrong lot; mapped obstacles may be missing or outdated. Trace all remaining No-cut areas, then trace the actual mowing area to replace yellow draft passes with white passes. If no parcel is found, tracing the lawn remains available. No automatic draft should be treated as an approved crew route.
- **Cut pattern preview.** Passes are clipped to the parcel, mapped obstacles and manually marked no-cut shapes. Arrows alternate by pass and labels mark start and finish. The preview is a geometric plan, not a measured GPS path.
- **No accounts, and data stays in one browser.** Customers and mow logs are saved in the browser's localStorage, so they do not sync between devices and are lost if browser data is cleared. For a real multi-user business you need a backend (e.g. Supabase or Firebase) for logins and a database.
- **Imagery and address search are free services with usage terms.** Esri World Imagery and OpenStreetMap Nominatim are fine for testing and light use. For a commercial launch, review their terms or switch to Mapbox / Google Maps with your own API key (change `ESRI` and `geo()` in `../pages/app.html`).
- **Lawn guidance:** The Lawn Health page uses logged cut direction, coverage and overlap to recommend one of four stripe directions. Select the grass type for a suggested mowing-height range. With a mapped address, the app requests Open-Meteo forecast data and suggests a possible dry day. It shows the reasons and allows you to see the suggested stripes on the map. This is an explainable rules-based planning aid, not a trained AI model, image-based grass identification, disease diagnosis, measured turf moisture or a guarantee of good conditions. Verify the lawn on site. Route simulation and some legacy metrics remain estimates; live crew tracking and shared data require a backend.
- **Weather licensing for a business:** The bundled Open-Meteo free endpoint is for non-commercial evaluation. Before using TurfOS in a commercial landscaping operation, connect a licensed commercial weather endpoint through your backend; keep provider keys on the server. Open-Meteo's commercial endpoint uses the same forecast fields. Credit the weather data provider in your customer-facing deployment.

## Installing it as an app (PWA)
Once the site is live on https, open `../pages/app.html`'s URL on the device:
- **Android / Chrome / Edge (desktop):** use the Install button in the address bar or menu.
- **iPhone / iPad:** Safari -> Share -> Add to Home Screen.
It then opens in its own window, works offline (map tiles still need internet), and asks the browser to keep its data.
Use Settings -> Backup data regularly; it saves a JSON file you can restore on any device.

## Store apps or desktop app (later)
- **iOS / Android stores:** wrap this same folder with Capacitor (capacitorjs.com). Needs Xcode/Android Studio; Apple Developer is $99/yr, Google Play is a one-time $25.
- **Windows / Mac:** wrap with Electron or Tauri.
- **Syncing across devices/crew:** needs a backend (Supabase / Firebase).
